# Техническое задание
## «Раскладка грузов» — автоматизация загрузки транспортных средств

> Версия: 1.0
> Статус: MVP реализован; документ фиксирует требования, фактическую реализацию и критический анализ с рекомендациями.

---

## 1. Общие сведения

### 1.1. Назначение
Программа предназначена для менеджера по логистике. Она автоматизирует расчёт раскладки грузов (ящики, паллеты, коробки) по кузову транспортного средства (ТС) и заменяет ручные вычисления.

### 1.2. Заказчик / пользователь
Менеджер по логистике. Один пользователь, локальное рабочее место (Windows 10/11).

### 1.3. Термины
| Термин | Значение |
|---|---|
| ТС | транспортное средство (фургон) |
| Единица груза | один ящик / паллет / коробка с габаритами Д×Ш×В и весом |
| Ярус | горизонтальный слой укладки (нижний/верхний) |
| Ряд | позиции груза, выстроенные вдоль длины кузова |
| Штабелирование | размещение груза поверх другого |
| Кантование | поворот единицы груза на бок (смена габаритной оси) |
| Задание на погрузку | перечень грузов (наименование, количество, габариты, вес) |
| Раскладка | итоговое размещение единиц в кузове с координатами |

---

## 2. Цели

1. Автоматический расчёт вместимости ТС с учётом габаритов груза и параметров кузова.
2. Оптимизация загрузки — минимизация незанятого объёма.
3. Исключение ошибок ручного расчёта.
4. Визуализация результата (схема) и отчётность (вес, объём, распределение).
5. Возможность ручной корректировки автоматически предложенного варианта.

## 3. Задачи

- Справочник ТС и грузов.
- Импорт задания на погрузку из файла и ручной ввод.
- Алгоритм раскладки с учётом правил (см. §6).
- Визуализация схемы и расчёт отчёта.
- Хранение истории заданий.

## 5. Функциональные требования

### 5.1. Справочник ТС
- CRUD записей: название, длина/ширина/высота кузова (м), грузоподъёмность (т), способ погрузки (зад / бок / верх).
- При первом запуске заполняется 5 типовыми ТС (Газель 4,2 м, Бычок 6,1 м, Тент 7,2 м, Еврофура 13,6 м, Фура 16,5 м).

### 5.2. Задания на погрузку
- Создание/удаление задания.
- Импорт из `.xlsx` / `.csv` (формат — §7).
- Ручное добавление строки груза (название, количество, габариты, вес).

### 5.3. Раскладка
- Выбор задания, ТС и режима ориентации.
- Запуск расчёта.
- Отображение схемы вид сверху с раскраской по типу груза и легендой.
- Отчёт: заполнение объёма (%), вес (т и %), центр тяжести, количество размещённых/неразмещённых, список неразмещённого.

---

## 6. Бизнес-правила раскладки

1. **Два яруса максимум.** Нижний ярус заполняется первым, верхний — на него.
2. **Тяжёлое/крупное — вниз.** Сортировка по высоте, затем по весу; сверху — более лёгкое.
3. **Ориентация** (выбирается пользователем):
   - фиксированная — длинной стороной вдоль фургона;
   - + поворот на 90° в плане;
   - свободная (кантование) — до 6 ориентаций.
4. **Правило ширины по борту загрузки:** при погрузке «зад»/«бок» в дальней от борта зоне (последние ~2 ряда) по ширине — не более 2 единиц рядом; ближе к борту — сколько помещается. При «верх» — ограничения нет.
5. **Грузоподъёмность** — жёсткое ограничение (не превышать).
6. **Цель** — максимальное заполнение объёма.

---

## 7. Формат входных данных

Импорт `.xlsx`/`.csv`; первая строка — заголовки.

| Колонка | Обязательность | Примечание |
|---|---|---|
| Название | да | наименование груза |
| Артикул | нет | — |
| Количество | да | единиц в строке |
| Длина/Ширина/Высота (мм) | да | габариты единицы |
| Вес (кг) | нет | суммарный по строке → вес единицы = вес ÷ количество |
| Штабелирование | нет | да/нет |
| Кантование | нет | да/нет |
| Допустимая нагрузка на груз (кг) | нет | пусто = не ограничено |

## 8. Фактическая реализация (что сделано в MVP)

| Компонент | Реализация |
|---|---|
| UI | WPF, 3 вкладки: ТС / Задания / Раскладка |
| БД | SQLite через системную `winsqlite3.dll` (P/Invoke), таблицы `vehicles`, `cargo_types`, `shipments`, `shipment_items`, `placements` |
| Импорт | встроенный парсер xlsx (первый лист, shared strings) и CSV |
| Алгоритм | жадная эвристика: сортировка «высота/вес убыв.» → first-fit bottom-left; поддержка опоры и 2 яруса |
| Схема | Canvas, вид сверху, прямоугольники по координатам, легенда |
| Отчёт | объём/вес/заполнение/центр тяжести/неразмещённое |

Проверено на примере: **46 единиц, 7 815 кг, 31,48 м³ → 46 из 46 размещено** в еврофуру 13,6 м (37 % объёма, 39 % грузоподъёмности).

## 9. Критический анализ

> Ниже — честная оценка: что сделано «достаточно», что — компромиссно, и что следует переделать.

### 9.1. С точки зрения разработчика ПО

| Проблема | Серьёзность | Комментарий |
|---|---|---|
| Алгоритм — жадная эвристика, **не гарантирует оптимума** | высокая | На сложных случаях проигрывает точным методам (CP-SAT/OR-Tools, метаэвристики). Для MVP приемлемо, для продакшена — нет. |
| Плотность укладки ограничена | средняя | First-fit bottom-left с точкой-кандидатом не использует «дыры» между ящиками; объём теряется. |
| Прямой P/Invoke к `winsqlite3.dll` | средняя | Работает офлайн, но хрупок: ручное управление памятью, нет типизированного слоя. `Microsoft.Data.Sqlite`/EF Core чище (при наличии сети). |
| Минимальный парсер xlsx | средняя | Только первый лист, без формул, стилей, числовых форматов, `.xls`. Не выдержит реальные выгрузки 1С. |
| Code-behind без MVVM | средняя | Логика в окне, не тестируется изолированно. |
| Нет unit-тестов | высокая | Алгоритм и парсер не покрыты; регрессии ловятся вручную. |
| Нет валидации входных данных | средняя | Некорректные габариты/вес молча принимаются. |
| Нет логирования/обработки ошибок в UI | низкая | Ошибки — в MessageBox/статусной строке. |

**Что можно было сделать лучше:** вынести алгоритм в чистую библиотеку с тестами; ввести абстракцию хранилища (интерфейс репозитория) поверх SQLite; перейти на MVVM; сделать импорт через проверенную библиотеку (ClosedXML/EPPlus) как только появится доступ к NuGet.

### 9.2. С точки зрения менеджера по логистике

| Пробел | Влияние на практику |
|---|---|
| **Нет порядка укладки/выгрузки** | При доставке по нескольким точкам груз должен грузиться «от последней точки к первой». Сейчас схема не учитывает маршрут. |
| **Нет осевых нагрузок** | Перегруз передней/задней оси — административное нарушение; нужен расчёт распределения веса по осям. |
| **Нет несовместимости грузов** | Опасные/хрупкие/пищевые грузы не разделяются (в ТЗ заявлено, но не реализовано). |
| **Правило ширины — упрощённое** | «Дальняя зона = 2×максимальный габарит» — эвристика, не подтверждённая реальной практикой погрузки. |
| **Нет ручной корректировки** | Логист не может поправить схему мышью (обязательное требование ТЗ). |
| **Нет отчёта в файл** | Менеджеру нужен печатный/экспортируемый отчёт (PDF/Excel) и схема для грузчиков. |
| **Допустимая нагрузка на груз не учитывается** | На хрупкий ящик нельзя ставить тяжёлый; сейчас игнорируется (по умолчанию «не ограничено»). |
| **Нет интеграции с 1С:ERP** | Данные переносятся вручную через файл; целевой сценарий — прямая выгрузка из «Задание на отгрузку». |
| **Нет негабаритных грузов** | Описаны только прямоугольные коробки; ТЗ упоминает негабарит. |

## 10. Рекомендации (приоритезировано)

### Приоритет 1 — обязательно к доработке
1. **Ручная корректировка схемы** (перетаскивание/поворот/удаление, пересчёт остатка).
2. **Валидация и нормализация входных данных** (положительные габариты, вес, единицы измерения).
3. **Unit-тесты** на алгоритм и парсер (эталонные сценарии: полная/частичная загрузка, перегруз, кантование).
4. **Экспорт отчёта** (Excel/PDF) + печатная схема.

### Приоритет 2 — качество и точность
5. Замена эвристики на более сильную (guillotine/skyline + локальный поиск) либо подключение точного решателя (Google OR-Tools) при появлении сети.
6. **Осевые нагрузки** и **центр тяжести** как ограничение, а не только отчёт.
7. **Порядок укладки** с учётом маршрута доставки (LIFO по точкам выгрузки).
8. **Несовместимость грузов** (справочник групп и правил).
9. Учёт **допустимой нагрузки на груз** при штабелировании.

### Приоритет 3 — платформа
10. MVVM + вынос логики в отдельную сборку.
11. Типизированный доступ к SQLite (`Microsoft.Data.Sqlite`) и миграции.
12. Интеграция с 1С:ERP (импорт формата выгрузки).
13. Установщик (MSIX) + подпись кода.
