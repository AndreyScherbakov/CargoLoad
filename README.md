# Раскладка грузов

Десктопное WPF-приложение для **автоматизации раскладки грузов по грузовым автомобилям**. Предназначено для менеджера по логистике: вместо ручных расчётов программа раскладывает ящики/паллеты/коробки по кузову ТС, показывает схему и считает заполнение объёма и веса.

- Платформа: **Windows 10 / 11**
- Стек: **WPF + C# + .NET 8**
- Сборка полностью офлайн, без NuGet-пакетов и внешних библиотек.

---

## Возможности (MVP)

- Справочник транспортных средств (5 типовых ТС, редактирование).
- Задания на погрузку: импорт из **Excel (.xlsx) / CSV** + ручной ввод.
- Алгоритм 2-ярусной раскладки:
  - тяжёлое/крупное — в нижний ярус, лёгкое — в верхний;
  - до 2 ярусов по высоте;
  - длинной стороной вдоль фургона (или выбираемая ориентация);
  - учёт грузоподъёмности;
  - правило ширины по способу погрузки (зад/бок);
  - цель — максимальное заполнение объёма.
- 2D-схема вид сверху с раскраской по типу груза и легендой.
- Отчёт: объём/вес, процент заполнения, центр тяжести, список неразмещённого груза.
- Локальное хранение: **SQLite** (история заданий и справочник ТС).

## Требования

- Windows 10 / 11 (x64).
- Установленный **.NET 8 Desktop Runtime** (для запуска) или **.NET 8 SDK** (для сборки).

## Быстрый старт

### Сборка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

Результат: `CargoLoad\bin\Debug\net8.0-windows\CargoLoad.exe`.

> Примечание: `build.ps1` перенаправляет домашние каталоги dotnet и NuGet внутрь рабочей папки
> (`.dotnet-home`, `.nuget`, `.appdata`, `.localappdata`), потому что песочница DSH запрещает
> запись в профиль пользователя. Вне песочницы сработает и обычный `dotnet build`.

### Запуск

```powershell
CargoLoad\bin\Debug\net8.0-windows\CargoLoad.exe
```

### Демо-режим (сразу с примером)

```powershell
CargoLoad\bin\Debug\net8.0-windows\CargoLoad.exe "Пример задания на погрузку.xlsx" --pack
```

Программа импортирует файл, выберет «Еврофуру (13,6 м)», выполнит раскладку и откроет вкладку «Раскладка».

### Сборка для передачи пользователю

Для обычного пользователя собирается **self-contained** версия — .NET устанавливать не нужно.

**Вариант 1 — один файл (удобно пересылать):**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File publish.ps1
```

Результат: `dist\CargoLoad.exe` (~68 МБ). Просто скопируйте файл и запустите.
При первом запуске рантайм распаковывается в `%TEMP%\.net` — нужен доступ на запись в `%TEMP%`.

**Вариант 2 — папка (надёжнее, ничего не распаковывает):**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File publish.ps1 -Folder -Output dist-folder
```

Результат: `dist-folder\` (~160 МБ, 460+ файлов). Запускать `CargoLoad.exe` из папки.
Для передачи — заархивируйте папку в ZIP.

**Вариант 3 — компактный (требует .NET 8 Desktop Runtime):**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File publish.ps1 -FrameworkDependent
```

**Где хранятся данные:** база `cargoload.db` создаётся в `%LOCALAPPDATA%\CargoLoad\`.
Если этот каталог недоступен, программа пишет базу рядом с `.exe` (portable-режим).
Поэтому приложение можно класть в `Program Files` — права администратора не нужны.

> Неподписанный `.exe` при первом запуске может вызвать предупреждение SmartScreen
> («Подробнее» → «Выполнить в любом случае»). Для распространения без предупреждений
> нужна подпись кода сертификатом.

## Формат файла импорта (.xlsx / .csv)

Первая строка — заголовки. Обязательные колонки: **Название, Количество, Длина (мм), Ширина (мм), Высота (мм)**.

| Колонка | Значение |
|---|---|
| Название | наименование груза |
| Артикул | (необязательно) артикул |
| Количество | число единиц в строке |
| Длина / Ширина / Высота (мм) | габариты одной единицы |
| Вес (кг) | **суммарный вес строки** (делится на количество → вес единицы) |
| Штабелирование | `да` / `нет` — можно ли ставить сверху |
| Кантование | `да` / `нет` — можно ли поворачивать ящик на бок |
| Допустимая нагрузка на груз (кг) | допустимый вес сверху (пусто = не ограничено) |

Скрипт поддерживает и CSV (разделитель `;`, `,` или табуляция).

## Правила раскладки (алгоритм)

1. **Два яруса максимум.** Нижний ярус заполняется первым, верхний ставится на него.
2. **Тяжёлое/крупное — снизу.** Груз сортируется по высоте и весу; на верхний ярус идёт более лёгкое.
3. **Ориентация** (выбирается на вкладке «Раскладка»):
   - «Длинной стороной вдоль» — фиксированная;
   - «+ поворот на 90°» — дополнительно поворот в плане;
   - «Свободная (кантование)» — все 6 ориентаций.
4. **Правило ширины по борту загрузки:** при погрузке «зад» или «бок» в дальней от борта зоне
   (последние ~2 ряда) по ширине — не более 2 ящиков рядом; ближе к борту — сколько помещается.
   При загрузке «верх» ограничения по ширине нет.
5. **Грузоподъёмность** — жёсткое ограничение; превышение не допускается.
6. **Цель** — максимальное заполнение объёма (жадная эвристика bottom-left / first-fit decreasing).

## Допущения (подтвердить на реальных данных)

- **Вес** в импортируемом файле — суммарный по строке, вес единицы = вес строки ÷ количество.
- **Правило ширины** для ТС «бок/верх» не применяется (загрузка сверху), для «зад»/«бок» — применяется.
- Все грузы совместимы (несовместимость — на v3).
